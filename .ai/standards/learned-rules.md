# Learned Rules

Generated by `python3 scripts/learned_rules.py build` from Approved LRN sections in `docs/logs/learned-rules.md`. Do not edit by hand: a rule appears here only after a human approves it with `/approve`.

Every builder and the AI reviewer load this file. A violation of a rule here is a Major finding.

## LRN L-1: missing-input-validation

- **Rule:** Add a `validate()` method to every DRF serializer that enforces cross-field DB constraints, and resolve each effective field value from `self.instance` before evaluating the constraint so that partial updates are checked correctly. Wrap every `model.save()` call in a `try/except django.db.IntegrityError` block and return HTTP 400 with a structured error — never let `IntegrityError` propagate as HTTP 500.
- **Applies to:** backend-builder; `src/backend/**` — all DRF serializers and API views that write model instances subject to multi-column or cross-field DB constraints.
- **Checked by:** AI pre-review checklist item: verify that every serializer with cross-field DB constraints has a `validate()` method that uses `self.instance` for partial updates, and that every view's `save()` call is wrapped in `try/except IntegrityError`. No automated lint rule currently enforces this pattern; adding a custom flake8 plugin would require a gate change — that is a human decision.

## LRN L-2: api-contract-field-mismatch

- **Rule:** Before writing any TypeScript API client interface or `CreatePayload` type, verify every field name and the required-field list against API-001 response schemas and the backing Django serializer's `fields` tuple in DBD-001; use exactly the serializer's field names with no aliases or renames. Never add a field to a TypeScript interface or payload type that is absent from both DBD-001 and the serializer's `fields` tuple for that model.
- **Applies to:** frontend-builder; `src/frontend/src/api/**` — all TypeScript API client files that declare interfaces or payload types representing backend model data.
- **Checked by:** AI pre-review checklist item: for every TypeScript file under `src/frontend/src/api/`, verify that each interface and payload type field name exactly matches the corresponding serializer `fields` tuple entry in the backend and the response schema in `docs/04-design/api-spec.md`; flag any discrepancy as Major. An automated alternative is `npx openapi-typescript docs/04-design/openapi.yaml -o src/frontend/src/api/openapi-types.ts` followed by TypeScript type-checking (`tsc --noEmit`), which would surface mismatches at CI time; adding this step to the automated gates requires a human decision.
