### New Findings

**NEW-MIN-001 -- Stale security event names in openapi.yaml endpoint description text**

- Severity: Minor
- File: docs/04-design/openapi.yaml, GET /audit/security-events/ description field
- Observation: The description text reads sign_in_success, sign_in_failed, account_lockout,
  temp_password_set, own_password_changed. Three names differ from the canonical values in DBD-001
  and BED-001: sign_in_success should be successful_sign_in; sign_in_failed should be
  failed_sign_in; temp_password_set should be temporary_password_set.
- Rule: Consistency layer -- same concept named identically across all artifacts.
- Suggested fix: Update the description to list successful_sign_in, failed_sign_in,
  account_lockout, temporary_password_set, own_password_changed.

**NEW-MIN-002 -- FinanceExportRow ticket_ref example uses 4-digit format**

- Severity: Minor
- File: docs/04-design/openapi.yaml, FinanceExportRow schema, ticket_ref example field
- Observation: The example value is TKT-0001 (4 digits). Every other ticket_ref example in the
  spec uses 5-digit format TKT-NNNNN (e.g., TKT-00042, TKT-00012). DBD-001 defines TKT-NNNNN.
- Rule: Consistency layer -- shared domain format applied uniformly.
- Suggested fix: Change example to TKT-00001 (5 digits).

**NEW-MIN-003 -- escalation_flag audit gap: DBD-001 documents the value but BED-001 has no service call**

- Severity: Minor
- File: docs/04-design/database-design.md audit_auditentry comment;
  docs/04-design/backend-design.md service layer
- Observation: DBD-001 lists field_name values for entity_type=ticket as status, priority,
  assignment, escalation_flag. BED-001 service functions assign_ticket, change_priority,
  update_ticket_status each call audit_event() with the matching field_name. However no BED-001
  service function documents writing field_name=escalation_flag. This leaves the DBD-001 comment
  as an orphaned value with no producer.
- Rule: Completeness layer -- every documented value has an owning code path.
- Suggested fix: Either add an escalate_ticket() service function in BED-001 that calls
  audit_event() with field_name=escalation_flag, or remove escalation_flag from the DBD-001
  comment if escalation is tracked only as a status change.

**NEW-MIN-004 -- F-code numbering conflict between TST-001 and API-001**

- Severity: Minor
- File: docs/04-design/test-strategy.md E2E journey table; docs/04-design/api-spec.md Purpose and Scope
- Observation: TST-001 assigns F-4=dashboard (story S-12) and F-8=audit trail (S-23). API-001
  Purpose and Scope defines F-3=service reporting/dashboards and F-7=audit trail. The two
  documents use different F-code numbering for the same features.
- Rule: Consistency layer -- shared identifiers used identically across artifacts.
- Suggested fix: Align both documents on the API-001 F-code set (F-3 for dashboards, F-7 for
  audit trail) since API-001 defines the canonical feature list for Phase 4.
